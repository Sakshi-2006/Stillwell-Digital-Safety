Project Title

Social Media Privacy Risk Assessment Framework

Objective

Build a tool that ingests social media profile data (exported JSON/CSV or API proxy), detects privacy risks (PII exposure, geo leaks, facial/child photos, metadata trails, weak settings), scores accounts, and generates actionable remediation steps plus a clear awareness dashboard.

Industry Relevance

Hiring teams, schools, and enterprises increasingly evaluate online footprints for safety and compliance; regulators emphasize data minimization and consent. A structured privacy risk scan + coaching helps students, job-seekers, and SMBs reduce doxxing, impersonation, and social-engineering exposure.

You are an expert Cybersecurity Engineer, Privacy Analyst, SOC Analyst,

Your task is to help me build a COMPLETE industry-oriented Cybersecurity project titled:

“Social Media Privacy Risk Assessment Framework”

IMPORTANT CONTEXT:

- This is a CYBERSECURITY course project.
- I want strong GitHub and LinkedIn proof of work.
- I am a beginner, so explain everything step-by-step.
- This must be a DEFENSIVE privacy and cybersecurity project.
- Do NOT scrape real social-media profiles.
- Do NOT collect private information about real people.
- Do NOT attempt to bypass privacy settings.
- Do NOT perform account enumeration.
- Do NOT identify, profile, or track real individuals.
- Do NOT access private accounts.

3. PRIVACY VS SECURITY
==================================================

Explain:

PRIVACY:
Controls how personal information is collected, shared, exposed, and used.

SECURITY:
Protects systems, accounts, and information from unauthorized access or misuse.

Example:

A social-media account may have a strong password but still expose too much
personal information publicly.

Therefore:

Strong Account Security ≠ Strong Privacy

Step 1 — Scope, Threat Model & Architecture

What are we doing?
Defining a framework that analyzes public profile data across platforms (X, Instagram, LinkedIn, Facebook, TikTok, GitHub), flags risky content/settings, assigns a score, and outputs step-by-step fixes and awareness tips.

Why are we doing it?
Profiles leak PII (emails, phone numbers, DOB), location trails (EXIF/geotags), routine patterns, and children’s images—fuel for scams and targeted attacks. A repeatable assessment makes privacy hygiene practical.

Inputs: exported JSON/CSV (safe demo), or a scraper proxy (for class, we use files).

Risk Engine: rule-based checks + lightweight NLP/vision (regex, keyword lists, optional OpenCV).

Scoring: weighted rubric → 0–100 (higher = more risk).

Outputs: risk items, remediation checklist, awareness micro-lessons.

Stack: Python 3.10, FastAPI, SQLite/Postgres, React/Vite, optional OpenCV for face detection; no live scraping required for demo.

# risk_engine.py
import re, json, math, pathlib
from datetime import datetime
EMAIL_RE = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}")
PHONE_RE = re.compile(r"(\+?\d[\s-]?){9,}")
WORKWORDS = {"badge","id card","hq","office","3rd floor","desk","shift"}
CHILD_HINTS = {"my kid","my child","daughter","son","#kids","#school"}
ROUTINE_HINTS = {"every day","daily","7am run","commute","school drop"}

WEIGHTS = {"pii":25,"geo":20,"child":15,"work":10,"privacy":10,"link":10,"handle":5,"tracker":5}

def load_json(path): return json.loads(pathlib.Path(path).read_text(encoding="utf-8"))

def score_profile(profile, posts):
    findings, score = [], 0

    # PII Exposure
    text_fields = " ".join([profile.get("bio",""), profile.get("email","") or "", profile.get("phone","") or ""])
    pii_points = 0
    if EMAIL_RE.search(text_fields): 
        findings.append({"cat":"PII","item":"Email visible in bio/profile","fix":"Remove email; use contact form or masked address."})
        pii_points += 10
    if PHONE_RE.search(text_fields):
        findings.append({"cat":"PII","item":"Phone number publicly visible","fix":"Remove phone; switch to business contact options."})
        pii_points += 10
    if profile.get("location"):
        findings.append({"cat":"PII","item":"Home city visible","fix":"Remove precise location; keep region-level only."})
        pii_points += 5
    score += min(WEIGHTS["pii"], pii_points)

    # Geolocation / Routine
    geo_points = 0
    for p in posts:
        if p.get("geo"):
            geo_points += 4
            findings.append({"cat":"GEO","item":f"Geotagged post {p['id']}", "fix":"Disable geotagging; remove past geo from sensitive posts."})
        if p.get("media",{}).get("exif",{}).get("created_local"):
            geo_points += 2
            findings.append({"cat":"GEO","item":f"EXIF timestamp leak in {p['id']}", "fix":"Strip EXIF before uploading."})
        t = (p.get("text") or "").lower()
        if any(h in t for h in ROUTINE_HINTS):
            geo_points += 2
            findings.append({"cat":"GEO","item":f"Routine disclosed in {p['id']}", "fix":"Avoid recurring time/place patterns in posts."})
    score += min(WEIGHTS["geo"], geo_points)

    # Children / Minors
    child_points = 0
    for p in posts:
        if p.get("media",{}).get("is_child_present"):
            child_points += 8
            findings.append({"cat":"CHILD","item":f"Child appears in post {p['id']} (public)","fix":"Make account private or remove/blur child faces."})
        t = (p.get("text") or "").lower()
        if any(h in t for h in CHILD_HINTS): 
            child_points += 2
    score += min(WEIGHTS["child"], child_points)

    # Workplace / School leaks
    work_points = 0
    for p in posts:
        t = (p.get("text") or "").lower()
        if any(w in t for w in WORKWORDS):
            work_points += 5
            findings.append({"cat":"WORK","item":f"Workplace detail in {p['id']}","fix":"Avoid badge/entry details; post generic work updates."})
    score += min(WEIGHTS["work"], work_points)

    # Privacy settings
    priv = profile.get("privacy",{})
    priv_points = 0
    if not priv.get("account_private", False):
        priv_points += 6; findings.append({"cat":"PRIV","item":"Account is public","fix":"Set account to private or limit story/audience."})
    if priv.get("show_activity", False):
        priv_points += 2; findings.append({"cat":"PRIV","item":"Activity status visible","fix":"Turn off activity/last-seen indicators."})
    if priv.get("allow_message_requests", True):
        priv_points += 2; findings.append({"cat":"PRIV","item":"Open message requests","fix":"Restrict who can message you."})
    score += min(WEIGHTS["privacy"], priv_points)

    # Linkage risks
    link_points = 0
    for url in profile.get("links", []):
        if "linktr.ee" in url or "pastebin" in url:
            link_points += 5
            findings.append({"cat":"LINK","item":f"Aggregator in bio: {url}","fix":"Ensure linked docs hide emails/phone; remove public spreadsheets."})
        if "github.com" in url:
            link_points += 3
            findings.append({"cat":"LINK","item":"GitHub linked; check for secrets/PII","fix":"Scan repos for .env/keys; add a SECURITY.md."})
    score += min(WEIGHTS["link"], link_points)

    # Handle reuse correlation
    handle_points = 0
    if profile.get("username") and any(u for u in profile.get("links",[]) if profile["username"] in u):
        handle_points += 3
        findings.append({"cat":"HANDLE","item":"Same handle across multiple sites","fix":"Consider unique handles or privacy mode on secondary accounts."})
    score += min(WEIGHTS["handle"], handle_points)

    # Simple tracker check for website (placeholder)
    track_points = 0
    if "myportfolio.com" in (profile.get("website") or ""):
        track_points += 3
        findings.append({"cat":"TRACK","item":"Personal site may include trackers","fix":"Add a cookie banner; reduce third-party scripts."})
    score += min(WEIGHTS["tracker"], track_points)

    return {"score": min(100, score), "findings": findings}

# app.py
from fastapi import FastAPI, UploadFile, File
from pydantic import BaseModel
import json, sqlite3, time
from risk_engine import score_profile

app = FastAPI()
db = sqlite3.connect("privacy.db", check_same_thread=False)
db.execute("""CREATE TABLE IF NOT EXISTS assessments(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts INTEGER, platform TEXT, username TEXT, score INTEGER, findings TEXT
)""")

class Payload(BaseModel):
    profile: dict
    posts: list

@app.post("/analyze")
def analyze(payload: Payload):
    res = score_profile(payload.profile, payload.posts)
    db.execute("INSERT INTO assessments(ts,platform,username,score,findings) VALUES(?,?,?,?,?)",
               (int(time.time()), payload.profile.get("platform"), payload.profile.get("username"),
                int(res["score"]), json.dumps(res["findings"])))
    db.commit()
    return res

@app.post("/upload")
async def upload(profile: UploadFile = File(...), posts: UploadFile = File(...)):
    prof = json.loads((await profile.read()).decode("utf-8"))
    pst  = json.loads((await posts.read()).decode("utf-8"))
    return analyze(Payload(profile=prof, posts=pst))

@app.get("/stats")
def stats():
    cur = db.cursor()
    cur.execute("SELECT COUNT(*), AVG(score) FROM assessments")
    total, avg = cur.fetchone()
    cur.execute("SELECT username, platform, score, ts FROM assessments ORDER BY id DESC LIMIT 20")
    recent = [{"username":u,"platform":p,"score":int(s),"ts":t} for (u,p,s,t) in cur.fetchall()]
    return {"total": int(total or 0), "avg_score": float(avg or 0), "recent": recent}

# vision_check.py
import cv2, numpy as np

def count_faces(image_path: str) -> int:
    img = cv2.imread(image_path)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    det = cv2.CascadeClassifier(cv2.data.haarcascades + "haarcascade_frontalface_default.xml")
    faces = det.detectMultiScale(gray, 1.2, 5)
    return len(faces)

Interview Question and Answer
-- 1. Interview Question: Explain your project.
-- Answer:
-- I developed a Social Media Privacy Risk Assessment Framework that evaluates
-- a user's social-media privacy practices without scraping or accessing their
-- actual accounts. The user completes a structured questionnaire covering
-- profile visibility, personal-information exposure, location sharing, posts,
-- connections, tagging, account security, third-party applications, social-
-- engineering awareness, and digital-footprint management. The system converts
-- these responses into category-wise risk scores and then calculates an overall
-- privacy risk score from 0 to 100. It identifies the highest-risk areas and
-- generates prioritized recommendations. I also implemented a privacy
-- improvement simulator that shows how the assessed score could change if the
-- user improves selected settings. The project follows privacy-by-design
-- principles and uses only synthetic or voluntarily supplied assessment data.


-- 2. Interview Question: What is the difference between privacy and security?
-- Answer:
-- Privacy is mainly concerned with how personal information is collected,
-- exposed, shared, and used, while security focuses on protecting accounts,
-- systems, and information against unauthorized access or misuse. They overlap,
-- but they are not identical. For example, a user could have a strong password
-- and MFA, meaning their account has useful security controls, but still keep
-- their phone number, full birthday, posts, and location publicly visible.
-- Therefore, good account security does not automatically mean good privacy.


-- 3. Interview Question: What is a digital footprint?
-- Answer:
-- A digital footprint is the information associated with a person's activities
-- and presence online. An active digital footprint includes information a user
-- deliberately shares, such as posts, comments, or profile information. Other
-- data can also be generated or collected through online interactions depending
-- on the service. In my project, I assess only self-reported privacy practices,
-- such as whether users review old posts, unused accounts, profile visibility,
-- and publicly shared information. I do not track users or collect their actual
-- online activity.


-- 4. Interview Question: How does your privacy-risk scoring system work?
-- Answer:
-- I divide the assessment into categories such as personal information,
-- location privacy, account security, connections, tagging, third-party apps,
-- social engineering, and digital footprint. Questionnaire responses are
-- converted into risk contributions for each category. Each category produces
-- a score between 0 and 100, where a higher value means higher assessed risk.
-- I then combine the category scores using configurable weights to produce the
-- overall score. The thresholds and weights are educational assumptions, so
-- they would need calibration before being used for professional risk decisions.


-- 5. Interview Question: How can social-media oversharing increase
-- cybersecurity risk?
-- Answer:
-- Oversharing can make more contextual information publicly available. Details
-- about someone's employer, college, interests, travel, family references, or
-- public events may sometimes help make fraudulent communication appear more
-- believable. Oversharing can also increase privacy exposure even when no
-- cyberattack occurs. My framework therefore identifies exposure categories
-- and recommends reducing unnecessary public information while avoiding the
-- assumption that every public detail automatically creates a security incident.


-- 6. Interview Question: Why did you include MFA in a privacy-assessment
-- project?
-- Answer:
-- Privacy and account security are connected. If an account is taken over, an
-- unauthorized person may gain access to private messages, photos, contacts,
-- or other non-public information. MFA adds another authentication layer and
-- can reduce account-takeover risk in many scenarios. Therefore, I include MFA
-- as part of the account-security category while keeping it conceptually
-- separate from information-exposure controls such as profile visibility.


-- 7. Interview Question: What privacy risks can third-party applications create?
-- Answer:
-- Users may authorize third-party applications to access parts of their social
-- account or related information. Over time, some integrations may no longer
-- be needed while retaining permissions. My framework therefore asks whether
-- users periodically review connected applications and remove unnecessary
-- access. This follows the principle of least privilege, where an application
-- should receive only the permissions required for its legitimate purpose.


-- 8. Interview Question: What is Privacy by Design, and how did you apply it?
-- Answer:
-- Privacy by Design means considering privacy throughout system design rather
-- than adding it only after development. In my project, I apply data
-- minimization by asking whether information is public instead of requesting
-- the actual information. For example, I ask whether a phone number is publicly
-- visible rather than asking the user to enter the phone number. I also avoid
-- collecting passwords, exact locations, private messages, home addresses, and
-- other unnecessary personal information. Assessment storage contains mainly
-- scores, finding types, and other minimal metadata.


-- 9. Interview Question: What is the privacy improvement simulator?
-- Answer:
-- The simulator lets the user see how changing specific privacy practices would
-- affect the framework's calculated risk score. For example, a user can
-- simulate making contact information private, disabling public real-time
-- location sharing, enabling MFA, enabling tag review, and reviewing third-party
-- applications. The system recalculates category scores and displays the
-- difference between the original and simulated assessments. I clearly label
-- this as a risk-model simulation rather than a guarantee that the user will be
-- safe from privacy or cybersecurity incidents.


-- 10. Interview Question: How did you make this project privacy-safe and how
-- would you improve it?
-- Answer:
-- I designed the application so it does not need to scrape social-media
-- profiles or collect unnecessary personal information. It uses synthetic or
-- voluntarily provided questionnaire responses, and the database stores
-- assessment scores and finding categories rather than sensitive details such
-- as passwords, phone numbers, home addresses, or exact locations. I would
-- improve the project by adding platform-specific privacy checklists,
-- configurable organizational policies, privacy-awareness quizzes, better
-- calibration of the risk model, accessibility and localization, assessment
-- comparisons over time, and an optional client-side mode where assessment
-- processing can remain on the user's device.
